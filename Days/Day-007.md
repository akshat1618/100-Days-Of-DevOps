
# Day 007 – Configure Passwordless SSH Authentication

**Challenge:** Configure Passwordless SSH Access to App Servers  
**Platform:** KodeKloud Engineer  
**Category:** Linux Administration / SSH Security  
**Source Server:** Jump Host  
**Source User:** `thor`  
**Target Servers:** App Server 1, App Server 2, App Server 3  
**Target Users:** `tony`, `steve`, `banner`  
**Status:** In Progress – App Server 1 Configured

## Objective

Today, I worked on an SSH authentication task from KodeKloud Engineer.

The requirement was to configure passwordless SSH authentication from the `thor` user on the Jump Host to all three application servers in the Stratos Datacenter.

Each connection had to use its respective sudo user:

- App Server 1 (`stapp01`) – `tony`
- App Server 2 (`stapp02`) – `steve`
- App Server 3 (`stapp03`) – `banner`

The objective was to allow the Jump Host scripts to connect to application servers without repeatedly requesting account passwords.

## Implementation

### Step 1: Verify the current user

```bash
whoami
```

**Explanation:** I used this command to verify that I was logged in as `thor` on the Jump Host.

### Step 2: Check the SSH directory

```bash
ls -la ~/.ssh
```

**Explanation:** This command lists the contents of the SSH configuration directory. I checked whether an SSH key pair already existed.

Initially, the directory contained only:

- `known_hosts`
- `known_hosts.old`

There was no existing SSH key pair.

### Step 3: Generate an SSH key pair

```bash
ssh-keygen -t rsa -b 4096
```

**Explanation:** I used this command to generate an RSA public-private SSH key pair for the `thor` user.

- `ssh-keygen`: Generates SSH authentication keys.
- `-t rsa`: Specifies the RSA key algorithm.
- `-b 4096`: Sets the RSA key length to 4096 bits.

I accepted the default file location and left the passphrase empty to enable non-interactive authentication.

The generated files were:

| File | Purpose |
|---|---|
| `~/.ssh/id_rsa` | Private key |
| `~/.ssh/id_rsa.pub` | Public key |

The private key stays on the Jump Host, while the public key is copied to the target servers.

### Step 4: Verify SSH key generation

```bash
ls -l ~/.ssh/
```

**Explanation:** I used this command to confirm that both SSH keys were generated successfully.

The output showed:

```text
-rw------- id_rsa
-rw-r--r-- id_rsa.pub
```

The permissions ensure that the private key is accessible only to its owner.

### Step 5: Copy the public key to App Server 1

```bash
ssh-copy-id tony@stapp01
```

**Explanation:** This command copies the public SSH key of `thor` to the authorized keys file of user `tony` on App Server 1.

I entered the password for `tony` during the initial key installation.

Verified output:

```text
Number of key(s) added: 1
```

### Step 6: Copy the public key to App Server 2

```bash
ssh-copy-id steve@stapp02
```

**Explanation:** This command installs the same public key on App Server 2 for user `steve`.

### Step 7: Copy the public key to App Server 3

```bash
ssh-copy-id banner@stapp03
```

**Explanation:** This command installs the same public key on App Server 3 for user `banner`.

### Step 8: Test passwordless SSH authentication

After installing the public key on all three servers, I used the following commands from the Jump Host:

```bash
ssh tony@stapp01
ssh steve@stapp02
ssh banner@stapp03
```

**Explanation:** These commands test SSH authentication using the private key stored on the Jump Host.

If the configuration is correct, the connections should work without requesting the target users' account passwords.

## Important Commands

| Command | What it does |
|---|---|
| `whoami` | Displays the current logged-in user |
| `ls -la ~/.ssh` | Lists SSH directory contents |
| `ssh-keygen` | Generates SSH key pairs |
| `-t rsa` | Specifies the RSA algorithm |
| `-b 4096` | Sets the RSA key length |
| `ssh-copy-id` | Copies the public key to a remote server |
| `ssh` | Connects to a remote server |
| `exit` | Closes the current SSH session |
