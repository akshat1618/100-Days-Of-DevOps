
# Day 008 – Install Ansible 4.7.0 Using pip3

**Challenge:** Install Ansible on Jump Host  
**Platform:** KodeKloud Engineer  
**Category:** Linux Administration / Configuration Management  
**Server:** Jump Host (`jump-host`)  
**User:** `thor`  
**Ansible Version:** `4.7.0`  
**Installation Method:** `pip3`  
**Status:** Completed

## Objective

Today, I worked on an Ansible installation task from KodeKloud Engineer.

The requirement was to install Ansible version `4.7.0` on the Jump Host using `pip3` only.

The Ansible binary also needed to be available globally so that all users on the system could execute Ansible commands.

The Jump Host would be used as an Ansible controller to manage other servers in the Stratos Datacenter.

## Implementation

### Step 1: Connect to the Jump Host

```bash
ssh thor@jump-host
```

**Explanation:** I connected to the Jump Host using the provided user account `thor`. This server would act as the Ansible controller.

### Step 2: Verify the current user

```bash
whoami
```

**Explanation:** I used this command to confirm that I was logged in as `thor`.

Verified output:

```text
thor
```

### Step 3: Check Python and pip3 versions

```bash
python3 --version
pip3 --version
```

**Explanation:** I checked whether Python 3 and pip3 were available on the Jump Host before installing Ansible.

### Step 4: Install Ansible 4.7.0 using pip3

```bash
sudo pip3 install ansible==4.7.0
```

**Explanation:** I used pip3 to install the exact required version of Ansible system-wide.

- `sudo`: Executes the command with administrator privileges.
- `pip3`: Python 3 package manager.
- `install`: Installs the specified package.
- `ansible==4.7.0`: Installs exactly Ansible version 4.7.0.

The installation also installed the required dependencies, including Ansible Core, Jinja2, PyYAML, and other Python packages.

Verified installation output:

```text
Successfully installed ansible-4.7.0 ansible-core-2.11.12
```

### Step 5: Verify Ansible version

```bash
ansible --version
```

**Explanation:** I used this command to verify that Ansible was installed and to check its version and installation location.

Verified output:

```text
ansible [core 2.11.12]
ansible python module location = /usr/local/lib/python3.9/site-packages/ansible
executable location = /usr/local/bin/ansible
python version = 3.9.19
```

### Step 6: Verify the installed package

```bash
pip3 show ansible
```

**Explanation:** This command displays information about the installed Ansible Python package, including its version and installation directory.

Verified output:

```text
Name: ansible
Version: 4.7.0
Location: /usr/local/lib/python3.9/site-packages
```

### Step 7: Locate the Ansible binary

```bash
which ansible
```

**Explanation:** I used this command to identify the location of the Ansible executable.

Verified output:

```text
/usr/local/bin/ansible
```

### Step 8: Check Ansible availability for root

```bash
sudo -u root ansible --version
```

**Explanation:** I used this command to check whether another user, in this case root, could execute Ansible.

The command returned:

```text
sudo: ansible: command not found
```

This indicated a PATH issue: the `sudo` environment could not locate the executable in `/usr/local/bin`.

The Ansible installation itself was successful, but global command availability still required verification and correction.

## What I Learned

This task helped me understand how Ansible can be installed using Python's package manager.

I learned how to:

- Install a specific Ansible version using pip3.
- Understand the difference between Ansible and Ansible Core.
- Install Python packages system-wide.
- Verify installed package versions using pip3.
- Locate executable binaries using `which`.
- Understand how PATH environment variables affect command availability for different users.

I also learned that installing a package system-wide does not automatically guarantee that every user's command environment can locate its executable.
