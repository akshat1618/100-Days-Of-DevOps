
# Day 006 – Cron Job Configuration on Linux

**Challenge:** Install Cronie and Configure a Root Cron Job  
**Platform:** KodeKloud Engineer  
**Category:** Linux Administration  
**Servers:** App Server 1 (`stapp01`), App Server 2 (`stapp02`), App Server 3 (`stapp03`)  
**User:** `root`  
**Schedule:** Every 5 minutes  
**Status:** In Progress – App Server 1 Verified

## Objective

Today, I worked on a Linux task from KodeKloud that involved configuring scheduled tasks using Cron.

The requirement was to install the `cronie` package on all three Nautilus application servers, start the `crond` service, and configure a cron job for the root user.

The cron job was required to execute every five minutes and write the text `hello` into `/tmp/cron_text`.

## Implementation

### Step 1: Connect to App Server 1

```bash
ssh tony@stapp01
```

**Explanation:** I used SSH to connect to App Server 1 (`stapp01`) using the provided account `tony`.

### Step 2: Install the Cronie package

```bash
sudo yum install -y cronie
```

**Explanation:** This command installs the `cronie` package, which provides the cron scheduling service. I used `sudo` because installing system packages requires administrative privileges.

- `yum`: Package manager used to install software.
- `install`: Installs the specified package.
- `-y`: Automatically confirms the installation.
- `cronie`: Package required for cron job scheduling.

### Step 3: Enable and start the cron service

```bash
sudo systemctl enable --now crond
```

**Explanation:** This command enables the `crond` service to start automatically during system boot and starts it immediately.

- `systemctl`: Manages system services.
- `enable`: Enables automatic startup.
- `--now`: Starts the service immediately.
- `crond`: Background service responsible for executing scheduled cron jobs.

### Step 4: Open the root user's crontab

```bash
sudo crontab -e
```

**Explanation:** I used this command to edit the root user's crontab. The `-e` option opens the cron configuration for editing.

### Step 5: Add the scheduled cron job

I added the following entry to the root crontab:

```cron
*/5 * * * * echo hello > /tmp/cron_text
```

**Explanation:** This cron expression schedules the command to execute every five minutes.

Cron schedule breakdown:

| Field | Value | Meaning |
|---|---|---|
| Minute | `*/5` | Every 5 minutes |
| Hour | `*` | Every hour |
| Day | `*` | Every day |
| Month | `*` | Every month |
| Weekday | `*` | Every day of the week |

Command breakdown:

- `echo hello`: Prints the text `hello`.
- `>`: Redirects the output and overwrites the destination file.
- `/tmp/cron_text`: File where the output is stored.

### Step 6: Verify the root cron job

```bash
sudo crontab -l
```

**Explanation:** This command lists the scheduled cron jobs configured for the root user. I used it to verify that the required cron entry was saved successfully.

Expected output:

```text
*/5 * * * * echo hello > /tmp/cron_text
```

### Step 7: Verify the cron service

```bash
sudo systemctl status crond
```

**Explanation:** This command displays the current status of the cron service, including whether it is running and its recent logs.

Verified output:

```text
Active: active (running)
```

### Step 8: Verify service startup configuration

```bash
sudo systemctl is-enabled crond
```

**Explanation:** This command checks whether the cron service is configured to start automatically when the server boots.

Expected output:

```text
enabled
```

### Step 9: Verify package installation

```bash
sudo rpm -q cronie
```

**Explanation:** This command checks whether the `cronie` package is installed and displays its installed version.

## What I Learned

This task helped me understand how Linux cron jobs automate repetitive tasks. I learned how to install and manage the Cronie package, configure scheduled tasks for the root user, and manage background services using `systemctl`.

I also learned how cron expressions define execution schedules and how output redirection can save command results into files.
